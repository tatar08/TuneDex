## 2. ลิงก์บิตเรตอื่นใน API สาธารณะ (API-VAR)

ยิงด้วย `curl --cacert <root CA> https://api.192-168-1-37.sslip.io/v1/catalog/radio` โดยไม่ต้องเข้าสู่ระบบ

| รหัส | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| API-VAR-001 | ก่อนเผยแพร่ร่างจาก ADM-VAR-002 | ทุกสถานีมี `"variants": []` (หรือรายการเดิม) ยังไม่เห็นลิงก์ใหม่ เพราะร่างไม่ถึงแอป |
| API-VAR-002 | เผยแพร่ร่างแล้วยิงซ้ำ | สถานีนั้นมี `variants: [{ streamUrl, codec: "hls", bitrateKbps: 64 }]` |
| API-VAR-003 | ลบทุกบรรทัดในช่อง บันทึก แล้วเผยแพร่ | กลับเป็น `"variants": []` |
| API-VAR-004 | ดู ETag | ค่า ETag เปลี่ยนเมื่อ variants เปลี่ยน และส่ง `If-None-Match` ค่าเดิมซ้ำได้ 304 |

## 3. สุขภาพสตรีมของลิงก์บิตเรตอื่น (ADM-HLTH-VAR)

ระบบตรวจสตรีมรันเป็นรอบ ถ้า staging ปิดการตรวจตามรอบไว้ (`STATION_CHECK_ENABLED` ไม่ได้เปิด) ให้ข้าม 001–003 แล้วรายงานว่าข้าม

| รหัส | ขั้นตอน | ผลที่ต้องได้ |
|---|---|---|
| ADM-HLTH-VAR-001 | เผยแพร่สถานีที่มีลิงก์บิตเรตอื่นเสียหนึ่งลิงก์ เช่น `https://example.invalid/x.mp3 mp3 32` แล้วรอการตรวจรอบถัดไป | การ์ด "สตรีมเล่นได้ไหม" ยังแสดงสถานะจากลิงก์หลัก และมีข้อความว่าลิงก์บิตเรตอื่นที่ 1 เล่นไม่ได้ |
| ADM-HLTH-VAR-002 | เปิด "ประวัติการตรวจ" | แถวของลิงก์บิตเรตอื่นมีป้าย "· ลิงก์บิตเรตอื่นที่ N" ส่วนแถวของลิงก์หลักไม่มีป้าย |
| ADM-HLTH-VAR-003 | ลบลิงก์ที่เสีย เผยแพร่ แล้วรอรอบถัดไป | ข้อความเตือนหายไป |
| ADM-HLTH-VAR-004 | กด "ตรวจตอนนี้" | ตรวจเฉพาะลิงก์หลัก ได้ผลภายใน 10 วินาที |
